This is a guide to building themes in a project from JSON files generated by Tokens Studio. It is intended for **developers**.

## Workflow

1. A designer creates or updates a set of design tokens within a theme, and pushes those changes onto a branch. See also: [Branch management](https://dentednerd.github.io/engineering-at-code/guides/tokens-studio-for-figma/2-branch-management/), [Creating a theme](https://dentednerd.github.io/engineering-at-code/guides/design-tokens-workflow/1-creating-a-theme/)
2. A developer pulls the branch onto their machine, and runs `npm run build:tokens` to test that the changes build correctly in Style Dictionary.
3. On a successful build, the developer opens a PR for the branch.
4. When the PR is approved and merge, the designer can pull the `main` branch in Tokens Studio to see their changes incorporated into the project.

## The build process

`npm run build:tokens` runs `build-tokens.js`, a Style Dictionary script that converts JSON files generated by Tokens Studio into CSS stylesheets containing the design tokens as CSS custom properties.

```js
// build-tokens.js
import { promises } from 'fs';

import { expandTypesMap, register } from '@tokens-studio/sd-transforms';
import StyleDictionary from 'style-dictionary';

register(StyleDictionary);

async function run() {
  const tokensDir = '_design-tokens';
  const themesFile = `./${tokensDir}/$themes.json`;
  const $themes = JSON.parse(await promises.readFile(themesFile, 'utf-8'));

  const configs = $themes.map((theme) => {
    const sets = theme.selectedTokenSets;
    const source = Object.entries(sets)
      .filter(([, val]) => val !== 'disabled')
      .map(([tokenset]) => `./${tokensDir}/${tokenset}.json`);

        return {
          log: { verbosity: 'verbose' },
          source,
          preprocessors: ['tokens-studio'],
          expand: {
            typesMap: expandTypesMap,
          },
          platforms: {
            css: {
              transforms: [
                'attribute/cti',
                'name/kebab',
                'border/css/shorthand',
                'fontFamily/css',
                'typography/css/shorthand',
                'ts/color/css/hexrgba',
                'ts/color/modifiers',
                'ts/descriptionToComment',
                'ts/opacity',
                'ts/resolveMath',
                'ts/shadow/innerShadow',
                'ts/typography/fontWeight',
              ],
            buildPath: 'public/styles/themes/',
            files: [
            {
              filter: (token) => {
                const isSource = token.filePath.match(/global/);

                return !isSource;
              },
              destination: `_${theme.name}-theme.css`,
              format: 'css/variables',
            },
          ],
        },
      },
    };
  });

  async function cleanAndBuild(cfg) {
    const sd = new StyleDictionary(cfg);

    await sd.cleanAllPlatforms();
    await sd.buildAllPlatforms();
  }

  await Promise.all(configs.map(cleanAndBuild));
}

run();
```

How it works:

- Style Dictionary reads `_design-tokens/$themes.json` to grab the metadata for each theme and its token sets.
- Any token sets marked 'disabled' in a theme are filtered out.
- Enabled token sets are converted into file paths at `./_design-tokens/${tokenset}.json`, to use as the source for that theme's build.
- Style Dictionary applies its own preprocessor for Tokens Studio JSON files.
- `expand.typesMap` uses Style Dictionary's `expandTypesMap` feature to split composite tokens into individual sub-tokens.

:::note[Example: typography tokens]
A single typography token needs to be expanded into separate `fontSize`, `lineHeight`, `fontWeight`, and `fontFamily` tokens.
:::

- We're exporting to CSS only, so `platforms` contains the `css` property. (If we were exporting to SCSS, for example, there would be a `scss` property rather than a `css` property. If we wanted to export to both platforms, both properties would be present.)
- The `transforms` chain is defined, combining:
  - Style Dictionary's built-in CSS transforms (`attribute/cti`, `name/kebab`, shorthand transforms, etc.)
  - Tokens Studio-specific transforms (`ts/color/modifiers`, `ts/resolveMath`, `ts/typography/fontWeight`, etc.)
- One file per theme is created in `public/styles/themes/`, named `_<theme.name>-theme.css`, in `css/variables` format.
- Any token whose source file path contains `"global"` is filtered out. Global tokens aren't used in CSS files; only alias and component tokens will be used, so global output isn't needed.
- The script builds all themes in parallel with `Promise.all`. For each generated config:
  - A StyleDictionary instance is created
  - The previous tokens are removed with `cleanAllPlatforms`
  - The new tokens are built with `buildAllPlatforms`
